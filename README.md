# Lighthouse 自动接单助手

适用于 [Lighthouse](https://app.lhdao.top/campaigns) 的 Chrome MV3 扩展，用于自动检测任务、接取评论类任务、打开目标 X 推文、生成并提交回复，并回到任务广场继续扫描。

## 功能

- 自动扫描 Lighthouse 任务广场并接取符合条件的评论任务。
- 支持任务倒计时监控、倒计时任务选中启动，以及最后 5 秒抢单窗口。
- 接取席位后等待 Lighthouse 自动打开目标 X；超过兜底等待时间时补开精确推文页。
- 在 X 页面执行关注、点赞、回复和任务组件提交流程。
- 当前 X 推文的灯塔“当前任务”面板显示“已完成”即结束本单，包括位于开放式 Shadow DOM 内的面板；不等待奖励到账。
- 任务完成后自动返回任务广场，异常时保留已接订单，避免串单。
- 确认未接到单时刷新广场并读取平台最新倒计时，不给未抢到的任务设置本地去重或批次等待；档位不符继续跳过。明确的账户限速仍按提示等待，已接单或动作结果未知时保留订单，避免重复执行。
- X 提交后等待平台自动验证，只读取本单结果；不主动切换标签、不进入进行中、不重开进度、不重复提交。确认官方完成后才返回任务广场。
- 广场刷新后 Chrome 仍在加载附属资源时，只读检查任务列表是否已就绪；慢加载额外等待最多 50 秒，不因固定 10 秒的整页加载判断直接误停。
- 侧边栏提供运行控制、倒计时面板、详细日志、回复记录和配置管理。
- 停止会取消当前流程，清空本轮订单状态、倒计时、统计和运行日志，仅保留一条停止记录；设置与回复历史保留，后台唤醒后保持停止。
- 任务广场连续等待 5 分钟仍无可执行任务时，先确认未尝试接单，再刷新并继续检测；已点击接单或结果未知的动作保留核对，不自动重发。
- 在广场等待或倒计时期间刷新网页，已确认尚未点击接单的扫描会自动恢复。每次锁位、接受邀请或接单确认点击前，先由后台保存并确认本次动作；已经开始点击、存在有效订单或旧版没有检查点的记录仍保留核对，不因刷新重发。
- 后台重启时，已持久确认未点击的扫描撤销旧页面执行意图后自动续扫；本单完成证据已保存时先收尾再接下一单，完成数不会重复累计。已接单但结果未明的记录继续保留。
- X 提交回执因刷新断开时保留提交记录，只读等待本单完成徽标；不重复提交，超时仍保留订单。发布评论回执未知时不自动重发。
- 单步按钮从所选步骤继续执行后续流程。接管前核对旧流程的取消回执，停止按钮取消整条步骤队列；保存设置失败后可重试，不会锁死按钮。
- 广场已加载但没有可执行评论任务时正常等待新任务，不再把只有原创任务或空列表误判为页面一直加载。
- 每次接单前启用网站“此推文含有未经验证的链接，请 KOL 接单时仔细分辨”提示的自动确认，刷新同一页面、停止后重新启动均会重新启用；停止时恢复原提示，其余弹窗保留。锁位等待被阻塞后会先核对本单回执，避免已锁位却被误判超时。
- 锁位点击前开始记录网站短暂提示，捕获 `react-hot-toast` 的状态消息。只有本次、同一详情、没有成功证据的明确拒单才能解除待核对状态；名额暂不可领及频率限制按平台要求等待，未知错误继续保留订单。
- 接续 X 提交前重新建立本单的完成监测。X 组件已经显示“当前任务 / 已完成”时直接结束本单，不再等待已消失的提交按钮，也不进入进行中查单；奖励发放中与实际到账分开记录。

- 锁位结果和中断后的订单核对共用同一套状态读取：同一订单明确显示席位已锁定、目标推文匹配且有可用 X 入口时，立即确认接单；旧接单提醒残留不再遮蔽成功回执。
- 停止在接单结果未知时，侧栏会只读核对当前订单。官方完成页必须显示匹配的“查看原推文”链接，才解除旧状态并允许继续检测；已锁位但未完成则保留本单供第 4 步接续。不会因页面刷新或打开侧栏而重新评论、提交、接单，发布评论本身结果未知的记录仍保持待核对。

## 0.7.106 不可接任务识别与点击前复核

- 任务卡片的操作区决定是否可接。平台按钮禁用时，即使整张卡片仍可点击，也不会绕过按钮打开详情；暂不可接单和未知的禁用状态都会跳过。
- 需灯塔严选资格、档位不符、当前等级不可、额度不足等资格限制优先于倒计时，在列表筛选、打开前复核和详情等待中一致处理。仅有“仅灯塔严选可接”标签不会排除具备资格的账号。
- 每次入口点击及随机等待后重新读取当前卡片状态；卡片失效或资格发生变化时停止本次点击，不改点外层容器。
- 正常放号倒计时继续等待；详情中的明确限制立即退出，使用现有未接单回执返回广场续扫。健康检查只读取当前详情，不再受背后其他任务卡片影响。
- 资格限制按平台最新状态重新判断，不新增永久忽略记录。新增 `task-availability.test.cjs` 覆盖真实卡片结构、禁用与无障碍禁用状态、倒计时优先级、点击竞争、资格恢复及两个锁位入口。

## 0.7.105 锁位后目标链接与原流程接续

- 修正真实页面在锁位成功后才出现目标链接时的确认顺序：只有同一个未更换的详情、完整锁位状态、有效 X 动作和目标链接同时成立才确认；已有目标绑定仍必须一致。
- 自动接单回执延迟时，在原执行链中只读复核本单，核对成功后接续，不再等侧栏轮询后留在手动处理状态。
- 对已核对锁位且没有评论/提交记录的原订单，显式启动会重新核对当前订单并接续自动流程，不清空后重新接单。
- 新增真实页面顺序及延迟回执、停止竞争、并发启动、错误目标回执回归；0.7.104 上 5 个复现场景失败，修后完整测试 683 项通过。

## 0.7.104 执行链整理

选中启动与全量检测在锁位后共用目标 X 接管、回复、提交、官方完成核对、返回广场和完成计数。选中启动只完成选定的一单，平台明确拒绝或延期放号时在该单内继续等待；任务下架、达到尝试上限或存在未知动作时给出明确终止状态。清理命令在运行权限仍有效时执行，不能先停机再发送收尾命令。

任务选择只保存身份，倒计时来自详情页的实时状态。刷新后的任务列表不会继续使用旧的选中副本，已经消失的任务不能从旧副本启动。后台重启时，确认未点击接单的选中流程恢复原选择；已经发出的未知动作保留核对。

回复和提交在发送前保存执行意图。连接丢失不会重发评论；提交回执丢失时，两种自动入口均只读核对本单是否完成。高级执行设置公开每轮完成上限及尝试上限。

`runner-lifecycle.test.cjs` 执行完整后台模块及真实消息发送、持久化和完成计数路径；Chrome 和页面边界离线模拟。它替代了选中流程中仅截取函数、模拟内部发送层的测试，覆盖明确拒单后同单重试、下架收尾、停止/重启竞争和动作发送前持久化。

## 安装

1. 解压发布包。
2. 打开 Chrome 的 `chrome://extensions`。
3. 开启右上角“开发者模式”。
4. 点击“加载已解压的扩展程序”，选择本项目目录。
5. 打开 Lighthouse 和 X，并点击扩展图标打开侧边栏。

## 配置

在侧边栏中设置：

- 运行模式、单次任务上限、接单尝试上限。
- 最低赏金、倒计时抢单、轮询间隔和锁席位超时。
- X 回复模式和 Lighthouse 自动提交。
- AI 模型名称、API Key 和系统提示词。
- 可选的运行时间段。
- 倒计时监控、最低监控赏金和语音提醒。

默认 AI 模型为 `gpt-5.6-terra`，可自行填写其他模型。AI 回复固定使用 `https://api.vayne.cc.cd/v1/responses`，接口配置只保留模型与 API Key 输入，不提供地址或协议入口。原地址不匹配的旧 Key 会清除，需要重新填写中转站 Key；系统提示词保持不变。

## 自动流程

```text
任务广场扫描
  -> 过滤任务
  -> 打开任务详情
  -> 锁定席位
  -> 打开目标 X 推文
  -> 执行 X 互动与回复
  -> 提交 X 任务组件
  -> 等待 Lighthouse 官方完成
  -> 返回任务广场
```

如果 X 页面没有自动跳转，扩展会在等待后使用目标推文 URL 兜底打开。已接取订单的后续步骤失败时不会继续抢新单，应先人工核对订单状态。

## 本地检查

项目没有 npm 构建步骤，使用 Node.js 运行检查：

```bash
node tests/behavior-check.mjs
node tests/review-check.mjs
node tests/regression-check.mjs
node --test tests/*.test.cjs
```

其中 `claim-recovery.test.cjs` 覆盖放号延期、继续扫描和已点击接单后的未知结果保护；`monitor-cards.test.cjs` 覆盖任务卡识别与重复项合并。`composite-task-types.test.cjs` 和 `composite-x-actions.test.cjs` 覆盖评论＋点赞的类型保留、任务面板延迟加载、动作执行与失败保护。`stopped-state-restore.test.cjs` 覆盖旧版已停止快照的订单和日志兼容读取、中断恢复，以及停止后重启不自动运行；`manual-stop-reset.test.cjs` 覆盖新版停止清理与设置、回复历史保留。`idle-refresh-recovery.test.cjs` 覆盖五分钟冷却等待后的安全刷新续扫，以及刷新、停止和延迟回执并发时的保护。`manual-takeover.test.cjs`、`manual-step-stop.test.cjs` 和 `step-queue.test.cjs` 覆盖单步接管、停止后取消后续步骤、迟到回执和异常后重试；`campaigns-readiness.test.cjs` 覆盖空广场、只有原创任务和未加载页面的区分。`submission-recovery.test.cjs` 覆盖提交回执丢失后的只读验收、超时保留、停止与保存失败，`completion-resume.test.cjs` 覆盖已完成的 Shadow DOM 面板在被动检查与提交恢复两个入口的一致识别。测试使用离线模拟，不会实际接单或发布评论。

也可以检查全部 JavaScript 语法：

```bash
find src tests -type f \( -name '*.js' -o -name '*.mjs' \) -print0 | xargs -0 -n1 node --check
```

## 权限与安全

扩展需要访问 Lighthouse、X、浏览器标签页、存储、脚本注入、通知和定时器权限，以完成自动任务流程。API Key 仅保存于扩展本地存储；不要把包含 API Key 的配置、截图或日志提交到公开仓库。
